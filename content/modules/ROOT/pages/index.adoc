== Why This Workshop Matters

OpenShift 5 is a significant release — not an incremental update.
It introduces structural changes across four areas that your customers will ask about before they plan an upgrade:

*AI as a platform feature, not a plugin.*
The MCP server and gateway ship as part of the OCP 5 control plane.
Any MCP-compatible AI client can connect, invoke live cluster tools, and drive autonomous workflows — without custom agents or sidecar deployments.
Agentic troubleshooting, on-demand dashboard generation, and upgrade risk scanning are available to every OCP 5 cluster out of the box.

*A new install and upgrade story.*
The OCP 4→5 upgrade path is architecturally different from minor-version upgrades.
The Operator Update Planner removes the manual compatibility research that blocked customers from upgrading confidently.
The Agent Installer now supports fully disconnected deployments with no dependency on an external image registry at install time.

*RHCOS 10 and the bootc lifecycle.*
Red Hat CoreOS 10 replaces rpm-ostree with a bootc image-based model.
Node OS updates are now atomic, rollback-capable, and do not require full node reprovisioning.
This changes how customers plan maintenance windows and reason about node compliance.

*Security hardening that customers will require.*
Post-quantum cryptography cipher suite support on the API server and ingress controller is a forward-looking requirement for regulated industries.
oc mirror v2 delta mirroring dramatically reduces the bandwidth and time needed to keep disconnected Operator catalogs current.

Completing this lab gives you hands-on evidence for each of these areas — not slide content, but terminal output and console screenshots you can use directly in customer conversations.
